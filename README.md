# cleanroom-recovery-ledger

`cleanroom-recovery-ledger` 是面向生物样本制备洁净室的环境偏离恢复放行工作台。它把微生物或粒子超限事件从影响范围冻结、结构化调查、纠正措施、连续复测推进到独立质量复核，并在批准后生成确定性 JSON 放行档案及 SHA-256 摘要。证据不完整、措施未完成、连续合格轮次不足或复核员参与过调查与纠正时，系统会阻止放行。

## 主要能力

- 以 `expected_revision` 拒绝陈旧页面提交，以持久化 `request_id` 返回一致的重复操作结果。
- 登记前按房间和闭区间规则预览冻结时间窗交叠；存在关联案件时必须显式确认，首版时间线会冻结关联编号与交叠摘要，案件列表和详情可双向导航。
- 纠正措施支持带理由和操作人的撤销，并保留原完成时间及证据；只有本案已撤销措施可被唯一替代，替代措施完成且有证据后才解除复测阻断。
- 微生物偏离要求 3 轮连续合格复测，粒子偏离要求 2 轮；失败会清零连续计数，并要求新增且完成补充纠正措施。
- 复测限值固定为案件适用限值，拒绝负数、非有限数值和放宽阈值；工作台按失败边界分段展示阈值差、计数贡献、剩余轮次和稳定的门禁原因。
- 快照使用临时文件同步后原子替换；事件流使用长度帧、连续修订和前序 SHA-256 摘要链。启动时会检查截断、篡改及聚合不变量。
- 批准后冻结案件，规范 JSON 中的集合稳定排序；档案可从保存内容独立复算并逐项显示验证结论。
- 每次档案校验记录校验人、`request_id`、时间、期望值、实际值及失败位置；记录存入旁路审计区，不改变案件修订、封存修订或规范摘要，历史失败不会被后续成功覆盖。
- Go 服务直接提供原生 HTML、CSS、JavaScript 工作台和同源 JSON API，不需要 Node 构建链。

## 构建与运行

标准构建：

```text
go build ./...
```

默认仅监听高位回环地址 `127.0.0.1:19091`，数据写入 `./data`：

```text
go run ./cmd/cleanroom-recovery -addr=127.0.0.1:19091
```

也可以用 `PORT` 指定端口；服务会绑定 `127.0.0.1:<PORT>`。`-data` 可指定其他本地数据目录。生产启动时会在接受请求前完成全部持久化完整性扫描，无法验证的数据会阻止服务进入可写状态。

浏览器打开 `http://127.0.0.1:19091/`，即可在同一页面完成案件登记、调查、纠正、复测、复核和档案校验。

## 测试与自检

运行全部单元测试和 HTTP 适配器测试：

```text
go test ./...
```

运行有界全流程自检：

```text
go run ./cmd/cleanroom-recovery -self-check -addr=127.0.0.1:19091 -self-check-timeout=12s
```

自检使用临时存储并启动真实回环 HTTP 服务，经公开 JSON API 完成微生物偏离的创建、调查、纠正、3 轮连续复测、独立批准与档案摘要验证，随后主动关闭服务并清理临时数据。

## 状态与持久化

案件正常经过 `investigating`、`correcting`、`retesting`、`pending_review` 和 `released`。复测失败或复核驳回会退回 `correcting`；驳回必须有理由。`released` 是冻结终态。

指定数据目录下包含：

- `cases/`：案件快照及 `request_id` 幂等响应索引。
- `events/`：长度校验的只追加事件帧和摘要链。
- `transactions/`：极短暂的提交恢复标记；正常提交后会同步删除，异常退出后由下一次启动确定性恢复。
- `archive-audits/`：档案完整性校验的只追加旁路记录和独立幂等结果，不参与案件修订。

放行档案保存在终态案件快照中，包含规范清单、封存修订、审批信息和 SHA-256 摘要。
